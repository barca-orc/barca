Manage runs, schedules and results on a server

Usage: barca serve [OPTIONS] [FILES]...

Arguments:
  [FILES]...  Python files or directories; default: discover the project

Options:
      --auth <AUTH>              Require project bearer tokens; overrides BARCA_SERVER_AUTH and [server] auth
  -p, --port <PORT>              Port to bind on [default: 8274]
      --host <HOST>              Bind address; 0.0.0.0 exposes the unauthenticated API [default: 127.0.0.1]
      --watch                    Reload changed source files; restart to discover new files
      --no-schedule              Disable scheduled runs
      --timezone <TIMEZONE>      Cron timezone: local, utc or an IANA name such as America/New_York [default: local]
      --read-only                Inspect only: refuse runs, never schedule, read compatible WAL metadata in place
      --drain-timeout <SECONDS>  Shutdown grace period in seconds; unfinished runs requeue (default: config or 30)
      --max-runs <N>             Maximum concurrent runs; others queue (default: config or CPU count)
      --capacity <N>             Limit total running step weight across server runs (experimental)
      --run-timeout <SECONDS>    Run time limit in seconds; 0 disables it (default: config or unlimited)
      --env <ENV>                Use a separate cache and history for this environment
  -h, --help                     Show concise command help
      --examples                 Show all command examples without running anything

Examples:
  barca serve                                # every file in the project; files added later need a restart
  barca serve pipeline.py                    # HTTP API on 127.0.0.1:8274 plus the scheduler
  barca serve pipeline.py --port 8400        # custom port

All examples: barca serve --examples
More: barca docs scheduling
