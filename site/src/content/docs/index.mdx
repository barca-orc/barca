You mark functions with `@asset`, `@sensor` or `@task` and declare their inputs. The
`barca` binary, written in Rust, reads the source without importing it, works out what
needs to run, and runs it in Python worker processes. Results are stored as files under
`.barca/`. An asset runs again only when its code or its inputs change; sensors and tasks
run every time.

There is no server to run and no configuration file to write. `barca serve` adds
schedules, an HTTP API and a web UI when you want them.

```python
# pipeline.py
from barca import asset


@asset()
def raw_data() -> list[dict]:
    return [{"x": 1}, {"x": 2}, {"x": 3}]


@asset(inputs={"data": raw_data})
def summary(data: list[dict]) -> dict:
    return {"count": len(data), "total": sum(d["x"] for d in data)}
```

```
$ barca get pipeline.py
[barca] 2/2 steps | done in 0.0s
Run 51fabebab1c0 | all assets in 0.135s (2 steps, 1 phase)

Value:
{
  "count": 3,
  "total": 6
}
```

## Install

```bash
uv add barca          # or: pip install barca
```

Python 3.12 or later; uv is not required. [Getting Started](/getting-started/) walks through
the first run.

	<Card title="Inspection commands" icon="magnifier">

		print JSON when piped.
	</Card>
	<Card title="Outside data comes in through a sensor" icon="information">
		An asset that reads a file or a bucket in its own body is computed once and then served
		from cache. Put a `@sensor` in front of it. See the
		[guide](/guide/#4-sensors-data-from-outside).
	</Card>
	<Card title="Large inputs" icon="seti:db">
		An unannotated parquet input is read in full with pandas. Annotate the parameter

		[Large inputs](/patterns/08-large-inputs/).

		The target comes first, then files: `barca get <asset> <files>`,
		`barca run <task> <files>`. `get` uses the cache. A task always runs. See the

	</Card>

## How it works

The binary parses your Python source and does not import it, so decorators and `inputs=` have
to be written literally. An asset is cached by run hash, which covers its code and its inputs,
not the bytes of its result. [Architecture](/architecture/#a-run) describes a run step by step,
and [Philosophy](/philosophy/) says what each design choice costs.
