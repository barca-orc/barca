## Install

```bash
uv add barca          # or: pip install barca
```

Python 3.12 or later. Wheels for macOS on Apple Silicon and Linux (x86-64 and arm64).

## The ideas

<CardGrid>
  <Card title="Assets are cached, tasks always run" icon="document">
    An `@asset` returns a value that barca stores and reuses until its code or an input changes.
    A `@task` does something (deploy, notify, migrate) and runs every time. `barca get` gets
    assets, `barca run` runs tasks. See [Assets](/reference/assets/) and
    [Tasks](/reference/tasks/).
  </Card>
  <Card title="Outside data comes in through sensors" icon="information">
    An asset that reads a file or a bucket in its own body is computed once and then served from
    cache. Put a `@sensor` in front of it so barca notices when the data changes. See
    [Sensors](/guide/#4-sensors-data-from-outside).
  </Card>
  <Card title="Partitions cache each key on its own" icon="list-format">
    One function runs once per customer, date or region, and each key reruns only when it
    changes, even across 200,000 keys. See [Partitions](/reference/partitions/).
  </Card>
  <Card title="A server when you want one" icon="setting">
    Everything above works on your laptop with a local `.barca/` directory. Add `barca serve` for
    cron schedules, a web UI and a run history the team shares. See
    [Share Results With a Team](/team-server/).
  </Card>
</CardGrid>

## How it works

The `barca` binary reads your Python source without importing it, builds the dependency graph and
runs each step in a pool of Python workers. A result is cached by a hash of its code and its
inputs, so a step reruns only when one of those changes. Because the graph is read statically,
decorator arguments such as `inputs=` must be written literally.
[Architecture](/architecture/#a-run) walks through a run step by step, and
[Philosophy](/philosophy/) says what each design choice costs.
